# Совместная работа

Несколько человек редактируют одну доску одновременно: изменения, курсоры и
выделения передаются в реальном времени.

```vue
<script setup lang="ts">
import { BoardEditor } from '@dskripchenko/board/vue'
import { httpProvider } from '@dskripchenko/board'

const provider = httpProvider({ base: '/api/boards/42', headers: { 'X-CSRF-Token': token } })
</script>

<template>
  <BoardEditor :provider="provider" :user="{ id: 'u7', name: 'Anna', color: '#ec4899' }" style="height: 720px" />
</template>
```

С поставщиком доска приходит с сервера (`modelValue` не нужен); пока она не
загрузилась, редактор доступен только для чтения. Панель справа вверху
показывает соединение и кто здесь — вы первым.

## Протокол

Сервер упорядочивает изменения; конфликты разрешаются по каждому свойству —
побеждает более поздняя запись в порядке сервера.

- Действие пользователя — это **пачка** [операций](model.md#операции):
  `{ client, cseq, ops }` — id клиента и его собственный счётчик.
- Клиент сразу применяет свою пачку и ставит её в очередь; сервер присваивает
  ей номер (`seq`) и рассылает всем, включая автора, — это и есть
  подтверждение.
- Клиент применяет пачки сервера по порядку к **подтверждённой** доске и
  показывает подтверждённую доску со своими неподтверждёнными пачками
  поверх. Пачка, пришедшая раньше времени, ждёт недостающую.
- Каждый клиент применяет одни и те же пачки в одном и том же порядке,
  поэтому все доски в итоге совпадают. Тесты пакета проверяют это на 1 000
  случайных сценариях с четырьмя клиентами и произвольным порядком доставки.

Правила:

- `set` — по каждому свойству побеждает более поздняя запись.
- `delete` побеждает: более поздние изменения удалённого объекта
  игнорируются.
- Отмена локальна: она отправляет обратную операцию к вашему последнему
  действию; чужие изменения вы никогда не отменяете.
- Двое одновременно печатают в одном стикере: побеждает более поздний текст
  (посимвольного слияния нет).

**Присутствие** — курсор, выделение, имя, цвет — идёт отдельно, не
сохраняется, не чаще 10 раз в секунду и гаснет после 30 секунд тишины.

## Поставщики

Поставщик — это транспорт; доска не знает, как передаются пачки.

```ts
interface BoardProvider {
  load(): Promise<{ board: Board; seq: number }>
  send(batch: Batch): void
  onBatch(cb: (batch: SeqBatch) => void): () => void
  resume?(seq: number): void
  presence?: { send(p: Presence): void; on(cb: (all: Presence[]) => void): () => void }
  status?: { on(cb: (s: 'connecting' | 'online' | 'offline') => void): () => void }
  close?(): void
}
```

| Поставщик | |
|---|---|
| `httpProvider({ base, wait?, interval?, headers? })` | HTTP-контракт ниже: long polling, упорядоченные отправки с повтором и нарастающей задержкой. |
| `new MemoryHub(snapshot?, latency?).provider()` | В одной странице или процессе: несколько редакторов рядом, тесты, демо. |

Поставщик на WebSocket — несколько строк поверх любого сокета: отправлять
пачки, вызывать слушателей `onBatch` с тем, что рассылает сервер.

## HTTP-контракт

| Запрос | |
|---|---|
| `GET {base}/snapshot` | `{ board, seq }` |
| `POST {base}/batches` | Пачка → `{ seq }`. Повторная отправка уже полученной пачки получает тот же `seq`. |
| `GET {base}/batches?after=N&wait=S` | `{ batches }` с `seq` > N. Сервер может удерживать запрос до S секунд, пока что-нибудь не появится; `410` означает, что N слишком старый — клиент перезагружает доску. |
| `POST {base}/presence` | Собственное присутствие → `{ presence: [...] }` (все, кто был виден за последние 30 с). |

Запросы несут cookies страницы (`credentials: same-origin`); прочие заголовки
(CSRF-токены) передавайте через `headers`.

## Сервер

`BoardServer` — эталонная серверная логика: любой хост оборачивает её
транспортом и хранилищем или портирует:

```ts
import { BoardServer } from '@dskripchenko/board'

const server = new BoardServer(await storage.load()) // { board, seq }
const { batch, fresh } = server.receive(incoming) // throws over the limits
if (fresh) broadcast(batch)
server.snapshot() // { board, seq } — persist it now and then
server.since(seq) // the batches after seq, or null (too old)
server.touch(presence) // presence of everyone active
```

Он нумерует пачки, игнорирует повторные отправки (по `client` + `cseq`),
ведёт журнал для возобновляющих работу клиентов и соблюдает ограничения
(500 операций на пачку, 10 000 объектов на доску). Проверяйте права до
`receive`: зрители не должны отправлять пачки.
