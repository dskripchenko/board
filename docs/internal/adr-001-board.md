# ADR-001. Доска (board): модель, отрисовка, совместное редактирование

Статус: **принято** · 2026-10-29

## Контекст

Нужен виджет бесконечной доски в духе Miro: базовые фигуры, стикеры, блоки,
заголовки, эмодзи, соединители — в визуальном стиле `@dskripchenko/flow`.
Доска должна работать в трёх средах и поддерживать одновременную правку
несколькими пользователями.

Порядок внедрения (решение автора):

1. виджет `@dskripchenko/board`;
2. `@dskripchenko/embed` — элемент `<dsk-board>`;
3. плагин Confluence (`confluence-embed`) — макрос `dsk-board`;
4. laravel-admin — отдельной итерацией.

Решения автора: **свой протокол синхронизации** (без Yjs); **картинок нет**;
набор объектов — фигуры, стикеры, блоки, заголовки и текст, соединители и
**эмодзи**.

## Решение

### 1. Пакет

`@dskripchenko/board`, та же раскладка, что у flow и diagrams:

| Вход | Что |
|---|---|
| `@dskripchenko/board` | Модель, операции, синхронизация, геометрия. Чистый TypeScript, без DOM и без зависимостей. |
| `@dskripchenko/board/vue` | `BoardEditor`, `BoardView` (только просмотр), панели. Peer: `vue`, `@dskripchenko/ui`. |
| `@dskripchenko/board/standalone` | Сборка для встраивания (`mount(el, options)`), как у flow. |

От flow **не зависим**: viewport, мини-карта, выделение и история
переносятся и адаптируются (это ~550 строк). Общий вид обеспечивают токены
UI-кита. Стилистика (сетка-точки, рамки групп, подписи, тени, палитра
`--dg-pie-*`) повторяет flow.

### 2. Модель

Версионированный JSON. Документ — плоская карта объектов; иерархия задаётся
ссылкой `parent` на блок.

```ts
interface Board {
  version: 1
  objects: Record<string, BoardObject>
  meta?: { title?: string; background?: 'dots' | 'grid' | 'none' }
}

interface Base {
  id: string                 // ULID, создаётся клиентом
  type: ObjectType
  x: number; y: number       // мировые координаты, левый верхний угол
  w: number; h: number
  rotation?: number          // градусы
  z: string                  // дробный индекс (порядок по глубине)
  parent?: string            // id блока-рамки
  locked?: boolean
}

type ObjectType = 'shape' | 'sticky' | 'text' | 'frame' | 'connector' | 'emoji'
```

| Тип | Свойства |
|---|---|
| `shape` | `kind`: `rect` · `rounded` · `ellipse` · `diamond` · `triangle` · `parallelogram` · `hexagon` · `star`; `fill`, `stroke`, `strokeWidth`, `strokeStyle` (`solid` · `dashed`); `text`, `textAlign`, `fontSize` |
| `sticky` | `color` (палитра из 8), `text`, `fontSize` (`auto` — подгон по размеру) |
| `text` | `text`, `variant` (`title` · `h2` · `body`), `color`, `align` |
| `frame` | `title`, `fill`; объекты с `parent` двигаются вместе с ним |
| `connector` | `from` / `to`: `{ id, side?: 'top' \| 'right' \| 'bottom' \| 'left' }` или `{ x, y }`; `route` (`straight` · `elbow` · `curve`); `startArrow`, `endArrow`; `label`; `stroke`, `strokeStyle` |
| `emoji` | `char` (одна графема), масштаб задаётся `w`/`h` |

- Текст — простой с небольшой разметкой (`**жирный**`, `*курсив*`, списки);
  рендер собственный, без HTML пользователя.
- Эмодзи рисуются системным шрифтом (без спрайтов): вид зависит от ОС —
  это приемлемо. Эмодзи также допустимы внутри текста стикеров и фигур.
- JSON Schema поставляется с пакетом (`schema/board.schema.json`).

### 3. Отрисовка

- Один SVG на сцену; трансформация viewport — на корневой группе.
- Текст в объектах — SVG `<text>` с собственным переносом (как в flow).
  Редактирование текста — HTML `contenteditable` поверх объекта, только на
  время правки.
- **Отсечение по видимой области** (по ограничивающим прямоугольникам
  с запасом): цель — плавная работа на 5 000 объектов.
- Соединители пересчитываются по привязкам при движении концов;
  маршрут `elbow` — ортогональный с обходом ограничивающих рамок
  (переиспользуем идею `route.ts` из flow).
- Инструменты: выделение (рамкой, Shift), рука, фигура, стикер, текст,
  блок, соединитель, эмодзи. Перемещение, изменение размера, поворот,
  привязка к сетке и направляющим соседних объектов, выравнивание и
  распределение, группировка в блок, порядок по глубине, копирование и
  вставка (буфер обмена в виде JSON доски), дублирование, блокировка.
- Мини-карта, масштаб 10–400 %, «показать всё», клавиатура (как в Miro:
  V, H, S, N, T, F, L, Delete, Ctrl+Z/Y, Ctrl+D, стрелки).
- Экспорт: PNG и SVG (всё или выделенное), JSON.
- Тёмная тема — через `data-theme` / `data-color-mode`, как у остальных
  виджетов.

### 4. Синхронизация (свой протокол)

Схема Figma: **сервер упорядочивает, конфликт решается на уровне свойства —
побеждает последняя запись по порядку сервера**.

**Операции** (одна операция — изменение одного объекта):

```ts
type Op =
  | { k: 'create'; id: string; obj: BoardObject }
  | { k: 'set'; id: string; props: Partial<BoardObject> }   // только изменённые свойства
  | { k: 'delete'; id: string }

interface Batch {          // атомарная пачка от одного действия пользователя
  client: string           // id вкладки
  cseq: number             // счётчик клиента
  ops: Op[]
}
```

Сервер присваивает пачке сквозной номер `seq` и рассылает её всем, включая
автора (как подтверждение).

**Клиент:**

- Применяет свою пачку сразу (оптимистично) и держит её в очереди
  неподтверждённых.
- Пришла чужая пачка → применить к подтверждённому состоянию, затем заново
  наложить свои неподтверждённые (свои свойства «перекрывают» чужие, пока
  сервер не решил иначе).
- Пришло подтверждение своей пачки → убрать её из очереди.
- Видимое состояние = подтверждённое + очередь своих.

**Правила слияния:**

- `set` — побеждает поздняя по `seq` запись для каждого свойства.
- `delete` побеждает всё: удалённый объект становится надгробием, поздние
  `set` к нему игнорируются. Надгробия чистятся при снимке.
- `create` с уже существующим id — игнор (id — ULID клиента, коллизий нет).
- Соединитель к удалённому объекту — конец «отрывается» в последнюю
  известную точку (решает клиент при отрисовке, модель не меняется).
- Порядок по глубине — дробный индекс; при совпадении индексов
  сравнивается id.
- Текст стикера — одно свойство: при одновременной правке остаётся текст
  поздней записи. Посимвольное слияние — вне рамок v1.

**Отмена и повтор** — локальные: отмена порождает обратную пачку (`set`
с прежними значениями, `delete` ↔ `create`) и отправляется как обычная.
Чужие правки не отменяются.

**Присутствие** — отдельный канал, не сохраняется: `{ user, name, color,
cursor: {x, y}, selection: id[], viewport }`, отправка не чаще 10 раз
в секунду, исчезает через 30 с тишины.

**Снимок:** `{ board, seq }`. Вход на доску — загрузить снимок, затем пачки
с `seq` больше снимка. Сервер пишет новый снимок каждые N пачек или
по таймеру.

**Проверка сходимости** — тест со случайными правками N виртуальных клиентов
с задержками и переупорядочиванием доставки: все клиенты обязаны прийти к
одинаковому состоянию.

### 5. Поставщик (транспорт)

Виджет не знает о транспорте:

```ts
interface BoardProvider {
  load(): Promise<{ board: Board; seq: number }>
  send(batch: Batch): void
  onBatch(cb: (b: Batch & { seq: number }) => void): () => void
  presence?: { send(p: Presence): void; on(cb: (all: Presence[]) => void): () => void }
  status?: { on(cb: (s: 'online' | 'connecting' | 'offline') => void): () => void }
}
```

- **Без поставщика** — однопользовательский режим, изменения наружу
  событием `change` (`v-model`).
- **HTTP-поставщик** (общий для embed и Confluence):

| Запрос | Что |
|---|---|
| `GET {base}/snapshot` | `{ board, seq }` |
| `POST {base}/batches` | пачка → `{ seq }` |
| `GET {base}/batches?after=seq&wait=25` | пачки после `seq`; `wait` — длинный опрос в секундах (сервер может ответить сразу пустым списком — тогда клиент опрашивает с интервалом) |
| `POST {base}/presence` | своё присутствие → присутствие всех |

- **WebSocket-поставщик** (laravel-realtime) — этап 4, в админке.

### 6. Среды

**embed** — `<dsk-board src|board-url mode="view|edit">`: `src` — JSON
доски (один пользователь), `board-url` — база HTTP-поставщика (совместно).

**Confluence (DC 10)** — макрос `dsk-board`, параметр — id доски:

- Хранение в собственных таблицах плагина (Active Objects): `BOARD`,
  `BOARD_BATCH` (журнал), `BOARD_SNAPSHOT`. Это общая база, поэтому на
  кластере всё работает без межузловых сообщений.
- Транспорт — HTTP-поставщик через сервлет плагина; длинный опрос с
  ожиданием в памяти узла и коротким интервалом проверки базы (≈1 с) —
  задержка между узлами до секунды.
- Присутствие — в кэше Confluence с TTL (кластерный кэш) или таблица с TTL.
- Права: просмотр доски — право просмотра страницы; правка — право
  редактирования; правят **прямо на странице**, без режима редактирования.
- Экспорт PDF/Word и показ при выключенном плагине — PNG-снимок доски, как
  у диаграмм (снимается браузером редактора).
- Копирование страницы — копия доски (новый id); удаление страницы —
  доска остаётся до очистки (задача администратора).

**laravel-admin** — отдельной итерацией: поле/раскладка `board`, таблицы,
канал laravel-realtime (нужен выпуск 0.1.0), присутствие через
presence-канал.

### 7. Ограничения v1

- До 10 000 объектов на доску, пачка до 500 операций и 256 КБ.
- Без картинок, комментариев, шаблонов, голосований, таймеров.
- Без посимвольного совместного текста.

## Этапы и критерии готовности

| # | Этап | Готово, когда |
|---|---|---|
| 1 | `board`: модель, отрисовка, редактор (один пользователь) | Все объекты и инструменты из п. 3, экспорт, тёмная тема, 5 000 объектов без рывков, модульные тесты, демо-страница |
| 2 | `board`: синхронизация | Операции, слияние, очередь, отмена; тест сходимости (≥ 1 000 случайных сценариев); `MemoryProvider` для двух вкладок в демо; HTTP-поставщик |
| 3 | embed | `<dsk-board>`, документация 4 языка, витрина |
| 4 | Confluence | Макрос, таблицы, сервлет, права, экспорт, показ при выключенном плагине, смоук-тест двух браузеров |
| 5 | laravel-admin | Отдельная итерация |

## Последствия

- Свой протокол проще отлаживать и хранить; цена — нет посимвольного
  слияния текста.
- В Confluence задержка доставки до ~1 с вместо мгновенной — плата за работу
  на кластере без WebSocket.
- От flow не зависим, поэтому часть кода холста дублируется; при третьем
  потребителе вынесем общий холст в отдельный пакет.

## Решённые вопросы

1. Пакет и элемент — `@dskripchenko/board` / `<dsk-board>`.
2. Репозиторий — GitHub (`dskripchenko/board`), как у остальных пакетов.
3. Confluence — одна доска на макрос: id доски создаётся при вставке
   макроса, копия страницы получает копию доски.
